# Хакатон-кит для Claude Code

Скиллы, агенты, правила и шаблоны для короткого хакатона (24–48 часов) с любым треком и спонсором. Сроки и правила конкретного хакатона живут в одном файле — `.claude/context/hackathon.md`, всё остальное от них не зависит.

## Установка (2 минуты)
Распакуй архив и запусти Claude Code из этой папки:
```bash
cd hackathon-kit && claude
```
Первая команда — `/hackathon-setup`: дай ссылку на сайт или правила хакатона, и кит заполнит расписание, контрольные точки и правила.

Чтобы скиллы и агенты работали в любой папке, поставь их глобально:
```bash
mkdir -p ~/.claude/skills ~/.claude/agents && cp -R .claude/skills/* ~/.claude/skills/ && cp .claude/agents/*.md ~/.claude/agents/
```

## Как устроен процесс
Главный принцип: больше всего токенов — на планирование (сильная модель), реализация — по плану на модели попроще, после реализации — жёсткое ревью снова на сильной модели.

| Когда | Скилл | Что делает |
|---|---|---|
| До старта | `/hackathon-setup` | Заполняет расписание, контрольные точки, оценку, правила |
| До старта | `/sponsor-brief` | Бриф на спонсора и гипотезы вероятных кейсов с заготовками идей |
| Старт | `/case-breakdown` | Тип трека, требования, 5 концептов с оценками, атака на лидера, SPEC с plan-note |
| Старт | `/deep-plan` | План реализации: контракты, шаги с проверяемыми критериями, зоны файлов, какая модель что делает |
| Старт | `/kickoff` | Репозиторий из шаблона и харнесса, первый коммит, деплой скелета, доступ для организаторов |
| Весь хакатон | `/checkpoint` | Сверка со SPEC и временем, что резать, задачи по ролям |
| После каждого шага | `/verify` | Сборка, типы, линтер, тесты, запуск без ключей, секреты, diff — готово или нет
| После каждой фичи | `/hard-review` | Параллельные ревьюеры ищут баги и халтуру, каждая находка проверяется |
| Перед сном | `/overnight` | ТЗ для автономной ночной работы модели в отдельной ветке |
| Перед сдачей | `/ai-evals`, `/jury-readme`, `/demo-capture`, `/submit-check` | Метрики, README для жюри, медиа, предсдаточный аудит |

**Агенты:** `build-error-resolver`, `code-auditor` и `tech-jury` (на сильной модели), `playtester`, `game-designer` (для геймдева).

**Защита в каждом проекте:** guard-хук блокирует force-push, `git reset --hard`, массовый откат, коммит `.env` и ключи в коде — особенно важно ночью, когда модель работает одна. `bash .claude/bin/overnight.sh` запускает ночную работу в отдельном worktree и ветке, `main` не трогается.

**Шаблоны** (работают без ключа, в mock-режиме):
- [templates/ai-service/](templates/ai-service/) — Python FastAPI + LLM со структурированными ответами, эвалы с метриками, ML-бейзлайн.
- [templates/web-game-3d/](templates/web-game-3d/) — 3D-город в браузере с NPC на LLM: память, отношение к игроку, действия.

План по часам и чек-листы — в [PLAYBOOK.md](PLAYBOOK.md).

## Полезные официальные плагины
Внутри Claude Code:
```
/plugin install frontend-design@claude-plugins-official
/plugin install feature-dev@claude-plugins-official
/plugin install pr-review-toolkit@claude-plugins-official
/plugin install security-guidance@claude-plugins-official
```
Если маркетплейс не найден, сначала выполни `/plugin marketplace add anthropics/claude-plugins-official`.
Встроенные скиллы ставить не нужно: `/claude-api` (актуальное API Claude), `/code-review`, `/security-review`, `/simplify`.

Работаете в Cursor или Codex? Скопируй `harness/CLAUDE.md` в `AGENTS.md` своего проекта: правила подойдут, а файлы скиллов можно давать агенту как инструкции.
