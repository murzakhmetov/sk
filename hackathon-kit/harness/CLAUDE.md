# Режим хакатона

Сроки, контрольные точки, правила и способ оценки — в `.claude/context/hackathon.md`. Кейс — в `docs/CASE.md`, бриф спонсора — в `.claude/context/`.
Каждое действие должно повышать шанс на победу: рабочий end-to-end продукт без багов под одну задачу и репозиторий, который жюри поймёт за 5 минут.

## Приоритеты
1. Сквозной демо-сценарий работает, `main` всегда запускается.
2. Требования кейса закрыты (`docs/CASE.md`, `docs/SPEC.md`).
3. Качество AI-части подтверждено цифрами (`/ai-evals`).
4. README написан для жюри (`/jury-readme`).
5. Полировка.
Если задача не двигает пункты 1–4, сначала согласуй её с пользователем. Лишние фичи не добавляем: вертикально хороший продукт под одну задачу.

## Модели: где тратить токены
- **Планирование — на самой сильной модели и с максимумом токенов** (`/case-breakdown`, `/deep-plan`). Ошибка в идее или плане стоит дороже любой ошибки в коде.
- **Реализация по готовому плану — на средней модели** (сабагенты с `model: sonnet` или отдельные сессии с промптами из `docs/TASKS.md`).
- **Ревью после реализации — снова на сильной модели** (`/hard-review`, агенты `code-auditor` и `tech-jury`). Модели-исполнители халтурят, ревью это ловит.

## Как работаем
- Без SPEC и плана не кодим. Фичи нет в скоупе — скажи об этом до начала работы.
- Цикл короткий: шаг плана → проверка его критерия и `/verify` → коммит → push. Сборка красная — агент `build-error-resolver`, а не обход проверок. Коммиты маленькие, в стиле Conventional Commits, на английском.
- В параллельных сессиях работай в своей зоне файлов из `docs/TASKS.md`. Общие конфиги (package.json, lock-файлы, CI) меняй осознанно и точечно.
- Секреты храни только в `.env*`, обновляй `.env.example`, значения ключей и токенов никогда не печатай.
- Guard-хук `.claude/hooks/guard.py` блокирует force-push, `reset --hard`, массовый откат, коммит `.env` и ключи в коде. Блок — не повод обходить: объясни пользователю, зачем команда, и пусть он решит сам.
- У каждого AI-вызова есть таймаут, валидация ответа по схеме, фолбэк и mock-режим без ключа. Демо не должно зависеть от API.
- Модели в коде решения задаются через env.
- Новые зависимости добавляй, только если они экономят часы. Работающий код без причины не рефактори.
- Код, идентификаторы и коммиты пиши на английском, UI, README и документацию — на языке кейса.
- Когда заметная фича готова, обнови её строку в таблице «Кейс → решение» в README.
- Если сомневаешься между двумя вариантами, бери тот, что быстрее показать в демо.

## Время
Сверяйся с расписанием в `.claude/context/hackathon.md` и с `date`.
- **КТ-1:** сквозное демо работает (`/checkpoint`).
- **Заморозка фич:** дальше только баги, ревью, тесты, README и медиа.
- **Целевая сдача:** за несколько часов до дедлайна. После дедлайна ни одного пуша.
Если задача угрожает контрольной точке, скажи об этом сразу и предложи, что срезать. Перед сном — `/overnight`.
