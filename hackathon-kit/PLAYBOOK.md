# PLAYBOOK — короткий хакатон без потерь

Время ниже — относительное: **С** — старт (кейсы открылись), **Д** — дедлайн. Точные даты — в `.claude/context/hackathon.md`. Пример для хакатона на ~37 часов.

## 0. Принципы
- **Нужен рабочий end-to-end продукт без багов.** Одна задача, сделанная вертикально и до конца, побеждает пять полусырых фич.
- **Не кодим сразу.** Сначала команда вместе выбирает идею: плохая идея в корне проигрывает при любом количестве фич.
- **Два типа треков.** Открытая проблема — побеждает правильная идея. Конкретная задача (ТЗ, метрика) — побеждает точное выполнение, ничего сверх ТЗ.
- **Токены — на планирование.** Сильная модель планирует и обсуждает идею, средняя реализует по плану, сильная ревьюит.
- **Ревью — второй по важности шаг** после планирования: модели халтурят, ревью убирает баги.
- **Если судят по репозиторию, README и есть питч:** первый экран, запуск с первого раза, цифры.

## 2. Доступ к репозиторию для организаторов
Если организаторы просят токен, чтобы контрибьютить от лица команды, fine-grained токен **не обязан давать доступ ко всему аккаунту**:
GitHub → Settings → Developer settings → Fine-grained tokens → Generate → Repository access: **Only select repositories** → репозиторий хакатона → Permissions: **Contents: Read and write** (Metadata: Read добавится сам) → Expiration: день после дедлайна.
Токен передавайте организаторам лично. Не вставляйте его в чаты с моделью, в код и в README. После хакатона отзовите.

## 5. Что ценит техническое жюри
1. Запуск с первого раза: 1–3 команды, mock-режим без ключей, живая ссылка.
2. Таблица «требование → решение → файл» в README.
3. AI по делу: структурированные ответы, действия, инструменты, гардрейлы, фолбэки.
4. Цифры: качество на размеченном наборе, latency, стоимость в масштабе спонсора.
5. Чистый код: модули, типы, тесты на ядро.
6. Честные ограничения и план внедрения.
7. Живая история коммитов на протяжении хакатона.

## 6. Правила боя
- Без SPEC и плана не кодим.
- У каждого AI-вызова есть таймаут, валидация, фолбэк и кэш демо-ответов.
- Каждые 1–2 часа: коммит, пуш, деплой. `main` всегда запускается.
- Секреты только в `.env*`.
- Фича не влезает в 2 часа и её нет в демо-сценарии — режем.
- После КТ-1 идею не меняем, только упрощаем.

## 7. Заготовки и честная игра
В `templates/` только инфраструктура без логики кейса. Репозиторий создаём после старта, первый коммит честно называется `chore: scaffold from team starter template`. Если организаторы запретили заготовки, берём только публичные генераторы. Харнесс (скиллы, агенты, плейбук) кодом решения не считается. Папка `.claude/` и `CLAUDE.md` в репозитории сдачи — нормально: так команда делит правила, а жюри видит AI-native процесс.
